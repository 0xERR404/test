# Установка через свой Git

Нужна **Ubuntu Server 24.04 LTS без рабочего стола** и пользователь с sudo. Первая установка требует доступа к репозиториям Ubuntu и Snap Store. Ваш Git может быть любым сервером с SSH или HTTPS.

## 1. Подготовить репозиторий

Распакуйте архив и загрузите **содержимое папки** `skud-ubuntu-prototype` в свой репозиторий. В его корне должны находиться `install.sh`, `update.sh`, `server.py`, `web/`, `scripts/` и `tests/`.

Никакой адрес Git в исходники вписывать не нужно. Не загружайте `data/`, пароли или SSH-ключи. `.gitignore` и `.gitattributes` уже включены; `.gitattributes` сохраняет правильные окончания строк Linux.

## 2. Клонировать на Ubuntu

В терминале Ubuntu или по SSH:

```bash
sudo apt update
sudo apt install --no-install-recommends git ca-certificates openssh-client
read -r -p 'Вставьте адрес своего Git-репозитория: ' SKUD_REPO
git clone -- "$SKUD_REPO" skud
cd skud
sudo bash install.sh
```

Git выполняется от обычного пользователя. Для закрытого репозитория используйте его обычный SSH-ключ или механизм HTTPS-аутентификации. Не вставляйте пароль/токен в адрес репозитория. Установщик не сохраняет и не запрашивает данные доступа к Git.

Одна команда `sudo bash install.sh`:

1. Проверит Ubuntu 24.04, systemd и отсутствие запущенного desktop.
2. Установит Python и snapd.
3. Проверит shell-синтаксис и запустит серверные тесты.
4. Сохранит копию существующей базы, если она уже есть.
5. Установит локальный сервер, Ubuntu Frame и полноэкранный WPE-интерфейс; включит автозапуск.

Экран входа: **operator / demo1234** при первой установке. Ранее изменённый пароль сохраняется. Установщик не перезагружает систему сам. Для проверки загрузки выполните `sudo reboot` после успешного завершения.

## 3. Обновлять через Git

Из той же папки, **без sudo**:

```bash
bash update.sh
```

Скрипт получает изменения текущей tracking-ветки командой `git pull --ff-only --no-rebase`, затем запрашивает sudo для установки. Адрес удалённого сервера берётся из настроек вашего клона. При локальных изменениях, отсутствии tracking-ветки, ошибке Git или расхождении истории установка не начинается. Поведение fast-forward описано в [документации Git](https://git-scm.com/docs/git-pull).

Перед заменой программы выполняются тесты и резервное копирование базы. SQLite, пароль и параметры темы сохраняются. После успешного обновления активный киоск перезапускается для загрузки новых файлов. Автоматического отката схемы базы нет; текущая версия её не изменяет.

Если вы уже сами выполнили `git pull` или перенесли новый архив:

```bash
bash update.sh --local
```

Дополнительные режимы:

```bash
bash install.sh --check              # Проверка без установки
sudo bash install.sh --server-only  # Сервер без настройки графического киоска
sudo bash install.sh --update       # Обновление из имеющихся исходников без Git/apt
```

## 4. Ограничить оператору доступ к ОС

Сначала проверьте отображение СКУД, перезагрузку и вход администратора по SSH. Для установки SSH-сервера, если его нет:

```bash
sudo apt install openssh-server
sudo systemctl enable --now ssh
```

Откройте отдельное SSH-подключение и убедитесь, что оно работает. Только затем из этого подключения:

```bash
sudo bash scripts/lock-console.sh --ssh-tested
sudo reboot
```

Оператор работает в СКУД; обслуживание выполняется через SSH. Включение ограничений консолей вынесено отдельно, чтобы не потерять доступ к машине до проверки графики. Полная защита физического доступа, firmware и загрузки с USB требует настройки конкретного компьютера.

Откат ограничений через SSH:

```bash
sudo bash scripts/unlock-console.sh
sudo bash scripts/disable-kiosk.sh
sudo reboot
```

## Диагностика

Журнал установщика: `/var/log/skud-prototype/install-*.log`.
Копии базы: `/var/backups/skud-prototype/`.
Исходники рабочей программы: `/opt/skud-prototype/`.
База и CSV: `/var/lib/skud-prototype/`.
Пароль: `/etc/skud-prototype/environment`.

```bash
systemctl status skud-prototype --no-pager
journalctl -u skud-prototype -n 100 --no-pager
snap services ubuntu-frame wpe-webkit-mir-kiosk
```

При ошибке тестов или резервного копирования установленный сервер не заменяется. Если сбой произошёл уже во время системной установки, изучите журнал и повторите установку после устранения причины. Не удаляйте каталог данных. Текущий установщик не откатывает системные пакеты или файлы приложения автоматически.

Синтаксис скриптов проверен в Bash; серверные тесты выполнены. Полный запуск установщика с apt/systemd/snap ещё необходимо проверить на Ubuntu. Это установщик прототипа с тестовыми данными, не образ промышленной СКУД.
