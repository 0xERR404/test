# СКУД · прототип для Ubuntu

Версия 0.1.0. Самостоятельный локальный стенд по макету с планом территории. Исходники можно целиком перенести в ваш собственный Git. Адрес репозитория и внешние сервисы приложению не нужны.

**Основная целевая система: Ubuntu Server 26.04 LTS, вариант minimized, без рабочего стола. Совместимость установщика с 24.04 LTS сохранена.** Python 3 + SQLite обслуживают интерфейс, Ubuntu Frame выводит его через WPE WebKit на весь экран. В приложении нет адресной строки, файлового менеджера или кнопки выхода в рабочий стол. После загрузки появляется экран входа СКУД.

Это прототип пользовательских сценариев и способа запуска. Контроллеры, реальные карты и двери не подключены. Все имена и события демонстрационные.

**Установка через свой Git:** пошаговая инструкция — [INSTALL.md](INSTALL.md). После клонирования достаточно `sudo bash install.sh`; для следующих версий — `bash update.sh` без sudo.

## Что уже работает

- Хаб: схематический план, пять точек доступа, выбор зоны, масштабирование, предупреждения, присутствие и последние события.
- Карточки точек: состояние, недавние события, подтверждаемые команды «Открыть однократно», «Блокировать», «Штатный режим». У точки без связи команды недоступны.
- Предупреждения: принятие с комментарием. Принятие не снимает неисправность.
- Мониторинг: точки доступа, фильтр проблемных, последний проход.
- Сотрудники и гости: поиск, фильтр присутствия, карточка пропуска, создание временного гостевого пропуска с проверкой срока и уникальности карты.
- Проверка доступа: базовая проверка срока пропуска и состояния точки. Это упрощённая модель, не полноценный расчёт прав.
- Журнал: фильтры по дате, точке, результату и тексту; CSV выбранных событий сохраняется на сервере в `data/exports` или `/var/lib/skud-prototype/exports`.
- Сводка: присутствие, разрешённые проходы, отказы и состояние оборудования, рассчитанные по базе.
- Тёмная и светлая темы, компактный и сенсорный размеры элементов.
- Вход, блокировка сеанса, повторный вход, отображение количества предупреждений на экране входа.
- SQLite сохраняет людей, режимы точек, подтверждения и до 1 000 последних событий между запусками. При запуске создаются 18 сотрудников; 12 из них изначально находятся на объекте.
- Имитация проходов по кнопке или каждые 8 секунд. Поток выключен по умолчанию, останавливается при блокировке сеанса.
- При потере сервера интерфейс показывает предупреждение и повторяет подключение.

Интерфейс выполнен на обычных HTML/CSS/JavaScript, без UI-фреймворков, CDN и загрузки шрифтов из Интернета. План и иконки — SVG в исходниках. Основные цвета: `#0C192D`, `#1C3353`, `#1258B1`, `#F3F6FC`, `#B6C6DC`, `#719BD0`. Светлая тема сохранена светлой целиком, без тёмной боковой панели.

## Быстро посмотреть на обычном компьютере

Нужен Python 3.10 или новее. Установка pip-пакетов и сборка Node.js не требуются.

```bash
cd skud-ubuntu-prototype
python3 server.py
```

На Windows можно выполнить `py -3 server.py`. Откройте в браузере **http://127.0.0.1:8080**. Это внутренний адрес на том же компьютере, не адрес вашего Git и не внешний сервер.

Вход: **operator / demo1234**. Данные создаются в папке `data`. Для остановки сервера в режиме разработки — Ctrl+C. Файл `web/index.html` нужно открывать через сервер: интерфейсу требуется API.

Для самостоятельного тестового набора можно указать другую папку:

```bash
python3 server.py --port 8081 --data-dir ./data-test
```

## Установка на Ubuntu Server 26.04 LTS

Используйте отдельный тестовый компьютер или VM с графическим выводом. Не устанавливайте GNOME/KDE или другой desktop. Установите Ubuntu Server, создайте администратора и включите OpenSSH для обслуживания. Сначала убедитесь, что можете подключиться к стенду по SSH.

Первичная установка системных пакетов и snap требует доступа к пакетным репозиториям. Само приложение после установки работает локально без Интернета.

```bash
sudo apt update
sudo apt install --no-install-recommends python3 snapd git openssh-server
sudo systemctl enable --now ssh
```

Перенесите проект вашим обычным способом через Git или архив. Все следующие команды выполняются **из корня проекта**:

```bash
sudo bash install.sh
```

Установщик сервера создаёт служебного пользователя `skud-prototype` без shell, копирует программу в `/opt/skud-prototype`, хранит данные в `/var/lib/skud-prototype` и включает `skud-prototype.service`. Повторный запуск обновляет код, сохраняя базу и пароль. Сервер слушает только loopback, не публикует порт в локальную сеть.

Скрипт киоска устанавливает `ubuntu-frame` и `wpe-webkit-mir-kiosk`, отключает launcher, задаёт локальную страницу, запускает службы и добавляет ожидание готовности сервера перед стартом WPE. Раскладки — английская и русская, переключение Alt+Shift. Настройки Frame предназначены для отдельного стенда и заменяют его текущий параметр `config`.

После проверки экрана перезагрузите Ubuntu вручную. Ожидаемый результат: загрузка ОС → полноэкранный экран входа СКУД → после ввода пароля хаб. Во время начальной загрузки ещё могут быть видны сообщения firmware/ядра. Отдельная настройка тихой загрузки в эту версию не включена.

### Пароль оператора

Для первого теста задан `demo1234`. Изменение выполняет администратор:

```bash
sudoedit /etc/skud-prototype/environment
sudo systemctl restart skud-prototype
```

В файле одна строка `SKUD_PASSWORD=ваш_пароль`. Не добавляйте этот файл в Git. После перезапуска все старые сеансы прекращаются. В прототипе один оператор; разделение ролей ещё не реализовано.

### Оператору — только СКУД

Начальный скрипт киоска оставляет консоли доступными администратору для проверки графики и восстановления. Когда СКУД стабильно запускается, **проверьте отдельную SSH-сессию** и выполните через неё:

```bash
sudo bash scripts/lock-console.sh --ssh-tested
sudo reboot
```

Скрипт запрещает новые локальные консольные входы, отключает автоматическое выделение VT, Ctrl+Alt+Delete и SysRq. Он не обрывает текущие сессии; окончательное применение требует перезагрузки. При обычной работе оператор видит только СКУД; переключение на другую VT не должно давать shell. Обслуживание остаётся у администратора через SSH.

Это начальный профиль ограничения стенда. Защита firmware/GRUB, загрузки с USB, физического доступа и всех комбинаций клавиш требует проверки на конечном оборудовании. Веб-интерфейс сам по себе не устанавливает эти ограничения.

Откат **по SSH**, из сохранённой копии проекта:

```bash
sudo bash scripts/unlock-console.sh
sudo bash scripts/disable-kiosk.sh
sudo reboot
```

Скрипт отката снимает только маски, записанные нашим скриптом, и восстанавливает прежнее значение SysRq. Приложение и база сохраняются.

## Как работать через ваш Git

В репозиторий идут `install.sh`, `update.sh`, `server.py`, `web/`, `scripts/`, `tests/`, `.gitignore`, `.gitattributes` и документация. У проекта нет заданного remote, стороннего хостинга или встроенного адреса репозитория. Runtime-данные исключены из Git.

Для получения и установки следующей версии из вашего репозитория, от обычного пользователя:

```bash
bash update.sh
```

Скрипт выполняет fast-forward обновление текущей tracking-ветки, тесты и резервное копирование, затем устанавливает программу через sudo. Копия SQLite сохраняется в `/var/backups/skud-prototype`. Сервер останавливается на время копирования; экран может кратко показать переподключение. Для уже полученных файлов используйте `bash update.sh --local`. Обновления запускаются вручную; автоматических миграций схемы нет.

## Проверка и обслуживание

```bash
systemctl status skud-prototype --no-pager
journalctl -u skud-prototype -n 100 --no-pager
snap services ubuntu-frame wpe-webkit-mir-kiosk
sudo snap logs ubuntu-frame -n 50
sudo snap logs wpe-webkit-mir-kiosk -n 50
python3 scripts/wait-ready.py
```

Если экран серый/тёмный, проверьте сначала службы snap и поддержку графики в VM. Если интерфейс запущен, но показывает отсутствие связи, проверьте `skud-prototype.service`. После исправления серверного сбоя открытая страница подключается автоматически; после сбоя загрузки самой страницы перезапустите WPE.

## Что проверено и что ещё нужно

На машине разработки проверены 7 серверных тестов: вход и выход, Origin/CSRF/Host, ограничение попыток входа, команды и сохранение состояния, принятие предупреждения, гостевые пропуска и срок действия, экспорт CSV, генерация событий. В Chrome проверены обе темы, компоновка 1280×720, основные переходы и формы. Отдельный отчёт — `VALIDATION.md`.

Установка systemd/snap, загрузка Ubuntu, WPE WebKit, работа видеодрайвера и ограничения локального доступа здесь **не исполнялись**: среда разработки — Windows. Скрипты подготовлены для ручной проверки на стенде, а не как уже проверенный образ ОС.

Образ Server 26.04 LTS доступен на [официальной странице Ubuntu](https://releases.ubuntu.com/26.04/). Проверки версии установщика принимают `VERSION_ID=26.04` и `24.04`. Snap-пакеты Frame/WPE устанавливаются из их текущих стандартных каналов: номер ОС не подставляется в название или канал snap. Документация Frame ниже остаётся в ветке `/24/`; это версия документации Frame, а не проверка версии установленной Ubuntu. Работу графики и WPE на Ubuntu 26.04 нужно проверить в целевой VM или на оборудовании.

Следующие этапы из исходного описания: реальные контроллеры и SDK/протокол, роли и права, аварии P1 и пожарный режим, мастера начальной настройки, считыватель и запись карт, печать пропусков/PDF, фотографии, расписания и зоны, полноценные отчёты, экранная клавиатура, автоматическая блокировка по бездействию, DPI 125/150%, резервирование и промышленный журнал аудита. Сейчас нельзя использовать стенд для реального управления доступом.

## Официальная основа установки

Команды Frame/WPE взяты из [Run Ubuntu Frame on your device](https://ubuntu.com/frame/docs/24/how-to/running-ubuntu-frame/on-your-device/). Параметры launcher, idle timeout, keymap и config описаны в [Ubuntu Frame configuration options](https://ubuntu.com/frame/docs/24/reference/ubuntu-frame-configuration-options/). WPE snap сопровождается сообществом, что отмечено в [руководстве по web kiosk](https://ubuntu.com/frame/docs/24/tutorial/make-a-secure-ubuntu-web-kiosk/). Ограничение Ctrl+Alt+Delete и SysRq основано на [Ubuntu Server: Console security](https://ubuntu.com/server/docs/how-to/security/console-security/).
